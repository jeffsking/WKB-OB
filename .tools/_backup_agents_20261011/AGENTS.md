## 2. 四类页面定义（卫材/采购场景）

### 2.0 语言规范（2026-09-29 起执行，适用于全部四类页面）

**英文为主 + 中文对照**：

- **正文主体用英文撰写**；每个小节标题、关键结论句、表格表头与关键行**附中文对照**（形如 `## Definition 定义`、`| Cost 成本 |`、`（中文：…）`）。
- **专业术语**首次出现时附中文或原文（视主语言而定），例如 `SAP（高吸水树脂）`、`NBSK（北方漂白针叶浆）`、`Rewet（回渗）`。
- **页面标题 / 文件名 / `[[wikilink]]` 文本**：英文优先；对象本身为中文专名时（中国公司、机构、中文报告）可用「中文名」或「English Name（中文名）」形式，**同一对象全库保持一致**。
- 源资料为中文时**需翻译**为英文正文，同时用中文对照保留原文关键表述与数字口径（不得因翻译丢失精度）。
- `key_claims` 等 front matter 列表项**同样英文为主、可附中文**。

> 修订原因：用户 2026-09-29 指示「后续编译的输出默认都是英文」，故将原「中文为主」改为上表规则。历史页面（2026-09-27 ~ 09-29 期间产出的中文页）不强制回溯改写，后续编辑时逐步补齐英文。

### 2.1 概念页 — `wiki/concepts/`

定义：技术或商业的理论、方法、术语、机理。
本库典型概念：芯体结构（全芯体/混合芯体/复合芯体）、SAP 吸水机理与保水性能、无纺布工艺（热风/纺粘/水刺）、胶黏剂类型（热熔胶/结构胶）、木浆等级与针叶/阔叶差异、纸浆价格指数（如 PIX NBSK）、成本加成定价、套期保值、双源采购策略等。

```yaml
---
type: concept
title: 混合芯体（Hybrid Core）
domain: [卫材研发, 芯体结构]        # 或 [采购, 成本分析]
status: seed | growing | stable     # 页面成熟度
updated: 2026-09-27
tags: [SAP, 芯体]
---
```

正文要求：一句话定义 → 机理/结构拆解 → 与相邻概念的 [[wikilinks]] → 关键参数表 → 来源引用。
**禁止**：未经来源支持的参数数字。没有来源的判断要标注 `[待验证]`。

**status 成熟度判据与晋升机制（2026-09-30 起）**：
- `seed`：仅有框架或占位，无实质可溯源内容
- `growing`：有实质内容，但未满足 stable 条件
- `stable`：**同时满足** ①≥2 个独立来源交叉验证（或 1 个高可信度来源充分支撑）；②页面无未决矛盾记录；③建立后经一次治理检查（§5）无事实修正；④定义、关键参数、来源三要素齐备
- 晋升由每周健康检查（§5）按判据批量出候选清单（只读脚本审计），**人工确认后**才改 `status: stable`；AI 不得自动晋升

### 2.2 实体页 — `wiki/entities/`

定义：具体的人、公司、机构、产品、技术平台。
本库典型实体：供应商（如三大绒毛浆巨头、SAP 厂商）、上游浆厂、代工厂、竞品产品线（各品牌纸尿裤型号）、认证机构、交易所与期货品种（木浆期货 SP）、行业协会等。

```yaml
---
type: entity
title: [供应商/公司名]
category: 供应商 | 浆厂 | 竞品 | 机构 | 交易所
relationship: 现有供应商 | 候选 | 竞品对标 | 信息源
updated: 2026-09-27
tags: [绒毛浆, NBSK]
---
```

正文要求：基本盘（产能、产地、主营）→ 合作/供货历史 → 价格与商务要点（**标注记录日期**）→ 相关概念 [[wikilinks]] → 来源引用。
**敏感信息处理**：报价、合同条款等商务信息只记要点与区间，不落原文附件之外的完整价格表；页面标题禁止含未公开合作方名称，用代号并在 front matter 记 real_name_hint。

### 2.3 源摘要页 — `wiki/sources/`

定义：`raw/` 中每份资料对应一页摘要 + 索引，是连接 Raw 层与 Wiki 层的桥。

```yaml
---
type: source
title: 2026Q3 木浆市场展望（研报）
source_type: 研报 | 公众号 | 会议纪要 | 报价单 | 行业新闻 | 工作日志 | 专利 | book | book-index
source_path: raw/ima_sync/xxx.md      # **一律指 RAW/ 路径（唯一判重锚，2026-09-30 起强制）；RAW 侧为空壳时正文从 RAW_FULL 同相对路径镜像读取**
original_link: https://...         # 微信/网页原文链接，如有
date_published: 2026-09-10
date_processed: 2026-09-27
credibility: 高 | 中 | 低          # 研报>官方>公众号>个人日志；判断依据写进正文
key_claims:                        # 从中提炼的核心论断（供概念/实体页回链）
  - "阔叶浆报价预计Q4承压"
pages_linked: ["[[PIX NBSK]]", "[[某浆厂]]"]
---
```

正文要求：3–8 句摘要 → 提炼的数字与结论列表 → 对应新建立/更新的 [[wikilinks]] → 原始文件路径。
**规则**：每份 raw 资料编译时必须先建源摘要页，再从摘要页出发建立概念/实体页；摘要页中的关键论断用 `key_claims` 沉淀，供概念页和实体页回链引用。
**长文文档（电子书）类型**：`source_type: book`（章节页/整书独存页，需填 `author/edition/publisher/year/isbn/original_language/parent_book`）；`source_type: book-index`（父书索引页，含 TOC 全章节内链）。编译约定见 `TEMPLATES/source.md` 附录与 `TEMPLATES/book_index.md`：**逐章编译、禁止整书巨页、重复整书跳过仅取元数据、preview/DeepRead 节选需核验标注**。

### 2.4 对比页 — `wiki/comparisons/`

定义：两个及以上相似对象的系统性异同比较。
本库典型对比：全芯体 vs 混合芯体成本与性能、针叶浆 vs 阔叶浆价格弹性、热风 vs 水刺无纺布在面层应用、多家供应商报价对比、竞品芯体方案拆解对比等。

```yaml
---
type: comparison
title: 全芯体 vs 混合芯体（成本/性能/供应链）
subjects: ["[[全芯体]]", "[[混合芯体]]"]
dimension: 性能 | 成本 | 供应链 | 综合
updated: 2026-09-27
tags: [芯体, 成本分析]
---
```

正文要求：对比维度表（必含"成本"与"供应链风险"两列）→ 各自适用场景 → 结论一句话 → 来源引用。
**规则**：对比页所有数字必须来自至少一个源摘要页，并在表格尾注出处。

## 3. 编译流程（处理 raw/ 新资料时）

1. 读取 `raw/` 新文件（判定"新"：无源摘要页的 `source_path` 指向该 RAW 路径；积压清单见 `.tools/_compile_backlog.json`，按统一锚重建）
2. 建 `wiki/sources/` 源摘要页
3. 识别资料中的核心概念、实体、对比点：
   - 已有页面 → 在页面追加验证记录/新信息，**不改原结论，追加并注日期**
   - 无页面 → 新建，按 §2 格式
4. 全部新页面用 `[[wikilinks]]` 与源摘要页互链
5. 更新 `index.md`（按 concepts / entities / sources / comparisons 四区追加条目）
6. 在 `log.md` 追加一条操作日志（日期 + 动作 + 涉及文件）

写入规范：**英文为主 + 中文对照（详见 §2.0）**——正文以英文撰写，小节标题 / 关键结论 / 表格表头附中文对照；术语首次出现附中文；标题与文件名英文优先；一个页面只讲一个主题；段落短，列表优先。

**长文文档（电子书）批量编译纪律（2026-09-29 起）**：
- 来源优先级：`Ebook Extract/<书名>/` 章节提取 > 整书文件；**禁止把整书文件（单文件可达 1.5MB）当单页**。
- 每章 = 1 个 `source_type: book` 的 source 页，`parent_book` 指向该书 `book-index` 索引页；每书 = 1 个 `book-index` 索引页（TOC 全章节内链）。
- 整书独存（无章节提取）→ 建 1 个轻量 `book` 页，不展开巨页。
- 重复整书（同书既有整书文件又有章节集）→ 整书文件跳过，仅作父索引元数据来源。
- `preview-` / `DeepRead` / `DeepBook` 等部分提取，编译前核验完整性并标注 `[节选]`。
- 概念/实体页仅对高价值章节派生 1–2 个，不自动泛滥。
- 代理纪律（沿用已验证）：同书串行、跨书并发；1–3 代理/波；按 `source_path` 查重跳过；禁改 `index.md`/`log.md`（写回执到 `.tools/compile_batches/_done/`）。

## 5. 治理规则（每周健康检查）

1. **矛盾检测**：同一事实在不同页面结论冲突 → 不擅自裁决，在双方页面各加 `> ⚠️ 矛盾记录（日期）：与 [[另一页]] 冲突，待人工确认`，并写 log.md
2. **孤立页面**：无任何其他页面引用 → 尝试补建链接；确实无关则标记 `orphan: true`
3. **断链检查**：修复失效 `[[wikilinks]]`
4. **索引核对**：`index.md` 与实际文件清单对齐
5. **时效提醒**：实体页中价格/供应信息超过 90 天未更新 → 在页面顶部加 `> 💡 信息已超90天，建议核实`
6. **状态字段防重复处理**：所有批量任务使用 `knowledge_update_status`（pending / done / manual_review）标记，已处理的资料不再重复编译

**人工确认边界（AI 不得自动执行，必须标记 manual_review）**：
- 删除任何页面
- 修改概念页/实体页的既有核心结论（只能追加）
- 商务敏感信息（具体报价、合同条款）的页面化
- 跨来源矛盾事实的取舍

## 7. 日志扫描规则（知识进化闭环）

> **状态：已启用（2026-09-30，用户决策）**。日志目录 `RAW/journal/` 已建立，每日扫描由 WorkBuddy 自动化（18:00）执行；扫描前先按 §7.5 判重，无未处理日志则当日零动作。

> 目标：只靠每天写简短工作日志，就能让知识库自动追加验证记录、沉淀经验教训。
> 原则：**低风险、可追溯、不改核心结论**——一切更新都是追加，不是改写。

### 7.1 日志书写规范（人工侧约定）

- 日志放 `raw/journal/`，命名 `YYYY-MM-DD.md`，每天一篇，几行即可
- 推荐随手记录的内容：供应商动态（涨价/停机/换贸术语）、SAP/浆价行情观察、试验或打样结果、谈判要点、踩坑教训、竞品拆解发现
- 日志中已有的 URL、文件路径是"锚点"，AI 扫描时要重点利用
- 日志永远只读：AI 不修改、不移动、不重命名日志文件

### 7.2 每日扫描任务

对 `raw/journal/` 中每篇 `knowledge_update_status ≠ done` 的日志执行：

1. 读取日志，识别值得沉淀的知识点，按四类判断：
   - **验证类**：日志中的观察验证（或推翻）了某概念/实体页的既有信息 → 对应页面**追加**一条带日期的验证记录
   - **实体动态**：供应商/竞品/浆厂的最新动态 → 更新对应实体页的"合作与供货历史"（追加，注日期）
   - **新概念/新实体**：日志里出现了库内没有的术语、公司 → 新建 seed 级页面
   - **教训类**：踩坑、返工、决策复盘 → 沉淀为概念页中的"经验教训"小节，或新建独立条目
2. 每篇日志建一个源摘要页（source_type: 工作日志，credibility 按低处理，仅供追溯）
3. 处理完的日志标记 `knowledge_update_status: done`（标记写在该日志对应的源摘要页 front matter 中，不改动日志本身）
4. 处理不了的（见 7.3）标记 `manual_review`，并在 log.md 中说明原因
5. log.md 追加一条"知识处理记录"：日期 + 日志文件名 + 涉及页面 + 动作（新建/追加/标记）

### 7.3 低风险自动更新 vs 人工确认

**可以自动追加（仍须注日期、可追溯）**：
- 给概念页追加"验证记录"：`> ✅ 验证（2026-09-27，来源 [[源摘要页]]）：某观察与页面结论一致/不一致`
- 给实体页追加供货动态、产能变化等事实性条目
- 新建 seed 级概念/实体页
- 补建 [[wikilinks]]

**必须标记 manual_review，禁止自动执行**：
- 日志与既有页面结论冲突（即使日志来自本人，也可能记错）
- 涉及具体报价、合同条款等商务敏感信息的页面化
- 基于日志推断出的新结论/新因果（AI 只搬运事实，不替你下判断）
- 删除或修改任何页面既有内容

### 7.4 历史经验自动召回（新项目/新任务场景）

当日志中出现新项目、新任务、新谈判（识别特征：新项目代号、新供应商名称、新物料）时：

1. 用关键词检索 `wiki/` 中相关实体页和概念页的历史记录

### 7.5 防重复与回溯
