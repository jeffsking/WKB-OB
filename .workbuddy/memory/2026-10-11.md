## 追加七：P0-B02/B03/B04 完成 + 判重口径缺陷（全库级）

### 最重要的发现：source_path 判重口径缺陷

**此前所有"未编译"数字都高估了。** 旧口径只检索单值 `source_path`，遗漏两类已登记情况：

1. **`source_paths` 多值字段**（登记同一页覆盖的多个 RAW 条目）
2. **跨专利合并页** —— 例：`WO2010071584A1 & US9162007...` 页同时登记 CN102245218B / JP5604444B2 / US9162007 等同族与副本

### 脚本坑：`\s*` 贪婪吞换行

正则 `r'^source_path:\s*(.+)$'` 的 `\s*` 会匹配换行，把后续多行一起吞进捕获组，**导致全库已登记 source_path 一条都匹配不到**，误判"全部未编译"。

**正确写法**：`r'^source_path:[ \t]*(.+)$'`

> 脚本不报错、结果"看起来合理"，只是全库归零。**凡涉及 front matter 逐字段解析，必须先打印 1 个样本验证匹配数不为 0。**

### Windows 文件名非法字符

`/` `,` `\` `:` 不可入文件名。本批连续踩坑 4 次。**建页前先对 `fn` 做非法字符清洗。**

### 重复件裁定口径

| 判据 | 结论 |
|---|---|
| 正文长度相同 + difflib > 0.999 + 首差异仅 front matter media_id | **同一 media 重复副本**，不单独建页 |
| 专利号出现次数一致，仅引文标注粒度不同 | **同一专利标注副本**，归并单页 |
| 同优先权日 + 同日申请 + 同族，但 PCT 号不同 | **同族不同专利，禁止合并** |
| 同一主体不同物料（官网 HTML vs 产品册 PDF） | **分别编译、互链** |

**US9162007 实例**：两份正文均 90,218 字符，sha1 不同（`63a8b2303e` / `d7cf3bafdc`），difflib 相似度 **0.9996**，首差异仅 front matter `media_id`。→ **sha1 不同 ≠ 内容不同**。

### CN 111134966 A：IMA 源侧损坏

缺 xref / trailer / `%%EOF`；重下 MD5 与本地完全一致（`b73eb774790a5f09e47464dc95bde4f3`）→ **损坏在源侧**。因缺 FontDescriptor + FontFile2 + ToUnicode，正文仅得乱码 CID，16 页附图内容对象在缺失区段。

**处置**：只建书目轮廓页 + 标 `manual_review` + 明确"不得用于 FTO 判断"。**这类件不能编技术内容，也不该硬编。**
